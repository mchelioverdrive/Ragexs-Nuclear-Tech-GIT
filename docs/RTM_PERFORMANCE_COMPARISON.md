# RTM Performance Changes — Previous vs Current

This is a short comparison of the performance changes documented in `RTM_PERFORMANCE_AUDIT.md`. It summarizes architecture and structural reductions; it is not a benchmark report. No aggregate CPU, frame-time, allocation-rate, or server-tick improvement has been measured.

| Area | Previous | Current | Evidence and remaining limit |
| --- | --- | --- | --- |
| Machine execution | Migrated machines ran from ordinary TileEntity updates, repeating recipe, topology, and resource checks even while idle. | 186 of 205 concrete machine-tree TileEntities resolve to event, scheduled, or coarse runtime strategies. World-scoped `MachineRuntime` owns dirty queues, typed deadlines, task slots, lifecycle identity, and shared polls. | Source census in the main audit. The 19 remaining default-path entries include proxy/helper tiles. This migration moved execution ownership; it did not remove all active one-tick simulation. |
| Scheduler replacement churn | Replacing a distant deadline left cancelled entries in the priority queue until their due time. | Cancelled entries are counted and the heap is rebuilt after at least 64 cancellations when they make up at least half the heap. | Ordering remains due tick then sequence. This bounds stale-entry retention without a linear queue removal per replacement. |
| Recipe and progress cadence | Stable production advanced progress and checked recipe resources on one-tick callbacks across the migrated recipe families. | Stable production settles elapsed loaded time to completion or resource boundaries; relevant mutations settle the previous interval, multi-lane factories reconcile in ascending lane order, and battery work or client progress projection is separated where supported. | The main audit names the migrated roster and every retained one-tick recipe/progress task with its dependency. General fluid transfer and coupled physical simulation retain their separate cadence. |
| Machine callback cadence | 224 immediate `scheduleMachineTransition(... + 1L, ...)` source lines were present at HEAD. | 239 matching lines are in the current source across 133 TileEntity classes. Foundry cooldown, Gas Dock launch movement, chimney visual expiry, and radio receive wakeup use a direct deadline, elapsed loaded ticks, a 20-tick effect boundary, and publication invalidation respectively. | This source-site count is not a performance score: migrated runtime tasks also need schedule sites. It includes wakeups and self-reschedules; the main audit classifies the remaining work. |
| Power endpoint work | Providers retried graph attachment together with their ordinary direct-neighbor output transaction. | Eighteen generator/provider families register persistent graph endpoints on lifecycle/structure changes and retain the direct receiver transaction at its original simulation point. Five periodic connection refreshes were replaced by invalidation; Detector's sole coarse registration poll was removed. | Graph attachment work is reduced. Direct neighbor delivery remains at its old cadence because receiver demand can change without a universal notification seam. No second energy network was added. |
| Power-network allocations and topology | Active network updates created temporary provider/receiver lists, demand buffers, endpoint pairs, and repeated graph refresh work. | Per-network scratch buffers are reused; persistent endpoint membership and dirty topology updates replace repeated membership reconstruction. Multi-position nodes are deduplicated per update, and battery keepalive reuses known membership. | These are structural allocation and traversal reductions. Active distribution remains server-tick work where rates or demand require it; no timing profile is recorded here. |
| Fluid-network allocations | Transfers rebuilt subscriber snapshots and demand data, and queried demand more than once during a transfer. | Pipe networks reuse subscriber and primitive demand buffers and use one demand query per subscriber for weighted transfer. | Transfer order, weights, and rounding behavior are retained. Broad producer-side fluid batching and endpoint demand notifications remain open. |
| Machine sync and recipe checks | Dirty machines serialized packets or repeated recipe/upgrade work while fields were unchanged; assembler recipe arrays and slot-index arrays were rebuilt during checks. | Opt-in dirty sync suppresses clean packet construction while preserving one-second baselines. Upgrade signatures reuse storage, and assembler/chemplant recipe and lane metadata are cached. | These changes avoid work on clean paths. Machines with direct third-party inventory mutation retain bounded fingerprints or compatibility polling. |
| Entity/world tick bookkeeping | Global entity maintenance copied a new world entity list each tick; some generators wrote large structures directly across neighboring live chunks. | Entity maintenance reuses a world-local snapshot. Large migrated terrain and structure generators compute deterministic chunk-owned output and write only the target chunk/population slice. | Migrated features include celestial bubbles, craters, bedrock-oil features, Moon ice pockets, volcanoes, and listed large structures. Several overworld oil and legacy direct decorators remain; seeded placement changes are recorded in the main audit. |
| OBJ/model loading and rendering | Separate Forge/HFR/HMF parsers retained per-face object graphs; reload coverage was inconsistent, and HFR uploads built temporary arrays and multiple buffers per group. | Active bundled model loads converge on cached prepared geometry with packed primitive vertices, range metadata, stable handles, and optional one-buffer GPU upload. All 479 resolved bundled geometry keys are shared by format/options; renderer consumers reuse handles. | Static source accounting found 385,859 faces and estimates at least 13.8 MB less retained CPU heap than the face-array minimum; this is not a heap measurement. Dynamic HMF and atlas-remapped rendering remain CPU submitted. |
| Renderer allocations and geometry selection | Icon-remapped model draws allocated temporary vectors; ordinary conductor geometry repeatedly selected model groups from connection masks. | Primitive rotation removes the temporary vectors; conductor rendering caches the 64 possible masks; TESR geometry is prepared and shared where inputs are static. | The main audit identifies dynamic render paths that still allocate. No frame-time or allocation profile is claimed. |
| Celestial sky calculations | Sky rendering and related queries independently rebuilt body/orbit positions and parent-chain relationships. | Per-world-provider snapshots reuse celestial/orbital metrics for a tick and partial tick; tidal-lock calculations walk relevant parent chains. | Existing sun-power, eclipse, orbital-angle, partial-tick, tidal-lock, and star-visibility rules remain in the current path. |
| Entity and chunk overhead | Rocket liquid checks scanned the full bounding volume, and ticket owners could retain/re-request redundant tickets. | Rideable rockets check local liquid material; ticket cleanup is tied to owner lifecycle, restored tickets replace redundant requests, and orphan tickets are released. | Ticket restoration, transfer, and forced-chunk ownership follow the shared ticket lifecycle described in the main audit. |
| Energy representation | Electrical and power readings mixed legacy HE, RF/EU boundaries, and display units. | Internal electrical storage and transfers use exact half-joule `long` quanta; watts express rates and compatibility conversion stays at API boundaries. | Legacy NBT counts load as quanta; new saves write versioned energy keys. The unit conversion is precision architecture rather than a measured speedup. |

## Current cadence pass at a glance

**Cadence totals:** 224 immediate `+ 1L` scheduling lines at HEAD; 239 are present in the current source across 133 TileEntity classes. One behavior uses a completion deadline, one integrates elapsed loaded ticks, one moved to a periodic effect deadline, and one now wakes from external publication. Five connection-refresh operations moved to invalidation; one coarse-poll registration was removed, and none were slowed. The larger source-site count reflects that runtime scheduling sites are an inventory, not a direct measure of work eliminated.

| Change | Previous | Current |
| --- | --- | --- |
| Foundry cooldown | Active countdown callback decremented each tick. | Stores remaining cooldown and schedules its loaded-time expiry. |
| Gas Dock launch | Position advanced one block per scheduled callback. | Position is projected from loaded elapsed ticks and a task is scheduled for the endpoint; buffered fluid still gets its original per-tick push attempts. |
| Chimney visuals | Server smoke timer updated every tick. | A 20-tick expiry ends the visual state; pending ash/soot retains one next-tick delivery. |
| Tuned radio receive | Receiver polled its tuned signal every tick. | RTTY publication wakes the receiver; listener ownership is removed on tile/world unload. A built-in test frequency that publishes every tick still causes a receive per publication. |
| Power links | Repeated generator work also retried graph attachment. | Graph attachment is separated from the direct transaction; direct delivery timing is preserved. |
| Connection renewal | Five controllers refreshed power/fluid connections every 20 ticks. | Those refreshes run from lifecycle and relevant dirty causes; one Detector coarse registration bucket was removed. |

Stable recipe accounting and lane reconciliation have moved to operation boundaries for the roster in the main audit. Remaining coupled recipe, heat, fuel, external transfer, and world-interaction callbacks are listed there by task and dependency; broader thermal, rotor, reactor, and fluid-transfer work remains a separate architectural area.
