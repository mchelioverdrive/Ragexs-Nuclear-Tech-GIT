# Performance architecture reference

RTM uses event-driven, scheduled and bounded coarse strategies where the simulation permits them. Continuous thermal/world interaction retains its required cadence. These are structural changes; no universal TPS, frame-time or allocation-rate speedup is claimed. For diagnostic chronology and source-review evidence use the historical index.

| Area | Current architecture | Evidence / limit |
| --- | --- | --- |
| Machine execution | 186 of 205 concrete machine-tree TileEntities resolve to event, scheduled, or coarse runtime strategies. World-scoped `MachineRuntime` owns dirty queues, typed deadlines, task slots, lifecycle identity, and shared polls. | Source census in the main audit. The 19 remaining default-path entries include proxy/helper tiles. This migration moved execution ownership; it did not remove all active one-tick simulation. |
| Scheduler replacement churn | Cancelled entries are counted and the heap is rebuilt after at least 64 cancellations when they make up at least half the heap. | Ordering remains due tick then sequence. This bounds stale-entry retention without a linear queue removal per replacement. |
| Recipe and progress cadence | Stable production settles elapsed loaded time to completion or resource boundaries; relevant mutations settle the previous interval, multi-lane factories reconcile in ascending lane order, and battery work or client progress projection is separated where supported. | The main audit names the migrated roster and every retained one-tick recipe/progress task with its dependency. General fluid transfer and coupled physical simulation retain their separate cadence. |
| Machine callback cadence | 239 matching lines are in the current source across 133 TileEntity classes. Foundry cooldown, Gas Dock launch movement, chimney visual expiry, and radio receive wakeup use a direct deadline, elapsed loaded ticks, a 20-tick effect boundary, and publication invalidation respectively. | This source-site count is not a performance score: migrated runtime tasks also need schedule sites. It includes wakeups and self-reschedules; the main audit classifies the remaining work. |
| Power endpoint work | Eighteen generator/provider families register persistent graph endpoints on lifecycle/structure changes and retain the direct receiver transaction at its original simulation point. Five periodic connection refreshes were replaced by invalidation; Detector's sole coarse registration poll was removed. | Graph attachment work is reduced. Direct neighbor delivery remains at its old cadence because receiver demand can change without a universal notification seam. No second energy network was added. |
| Power-network allocations and topology | Per-network scratch buffers are reused; persistent endpoint membership and dirty topology updates replace repeated membership reconstruction. Multi-position nodes are deduplicated per update, and battery keepalive reuses known membership. | These are structural allocation and traversal reductions. Active distribution remains server-tick work where rates or demand require it; no timing profile is recorded here. |
| Fluid-network pushes and invalidation | Separate tank network observation covers tracked mutations/restoration; reverse-membership detach covers direct subscriptions and merges. Forty-five fixed-list machine receivers opt into demand proofs. An unchanged zero-demand push can skip receiver traversal and demand queries after one proof. Successful pushes retain both existing demand-query passes and transfer formulas. | Producer callbacks and phases remain unchanged. Unknown endpoints, fair storage unions, storage tanks/barrels, direct neighbors, dynamic multiblock ports, and rate-limited active steps retain their cadence. No successful transfer or topology work is removed, and no measured speedup is claimed. |
| Machine sync and recipe checks | Opt-in dirty sync suppresses clean packet construction while preserving one-second baselines. Upgrade signatures reuse storage, and assembler/chemplant recipe and lane metadata are cached. | These changes avoid work on clean paths. Machines with direct third-party inventory mutation retain bounded fingerprints or compatibility polling. |
| Entity/world tick bookkeeping | Entity maintenance reuses a world-local snapshot. Large migrated terrain and structure generators compute deterministic chunk-owned output and write only the target chunk/population slice. | Migrated features include celestial bubbles, craters, bedrock-oil features, Moon ice pockets, volcanoes, and listed large structures. Several overworld oil and legacy direct decorators remain; seeded placement changes are recorded in the main audit. |
| OBJ/model loading and rendering | Active bundled model loads converge on cached prepared geometry with packed primitive vertices, range metadata, stable handles, and optional one-buffer GPU upload. All 479 resolved bundled geometry keys are shared by format/options; renderer consumers reuse handles. | Static source accounting found 385,859 faces and estimates at least 13.8 MB less retained CPU heap than the face-array minimum; this is not a heap measurement. Dynamic HMF and atlas-remapped rendering remain CPU submitted. |
| Renderer allocations and geometry selection | Primitive rotation removes the temporary vectors; conductor rendering caches the 64 possible masks; TESR geometry is prepared and shared where inputs are static. | The main audit identifies dynamic render paths that still allocate. No frame-time or allocation profile is claimed. |
| Celestial sky calculations | Per-world-provider snapshots reuse celestial/orbital metrics for a tick and partial tick; tidal-lock calculations walk relevant parent chains. | Existing sun-power, eclipse, orbital-angle, partial-tick, tidal-lock, and star-visibility rules remain in the current path. |
| Entity and chunk overhead | Rideable rockets check local liquid material; ticket cleanup is tied to owner lifecycle, restored tickets replace redundant requests, and orphan tickets are released. | Ticket restoration, transfer, and forced-chunk ownership follow the shared ticket lifecycle described in the main audit. |
| Energy representation | Internal electrical storage and transfers use exact half-joule `long` quanta; watts express rates and compatibility conversion stays at API boundaries. | Legacy NBT counts load as quanta; new saves write versioned energy keys. The unit conversion is precision architecture rather than a measured speedup. |

World mutation remains on the owning thread. Cached topology, recipe metadata and geometry require lifecycle/dirty invalidation; they do not authorize stale inventory, chunk or model ownership. Source census and complexity reductions are not runtime benchmarks.
